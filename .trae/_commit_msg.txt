ci!: 构建产物从 dist 分支迁移到 GitHub Releases assets；删除 dist 分支

背景（用户要求）：
  - Actions 构建的产物不应该再放在 dist 分支（dist 分支也是源码库的一部分，和 master 同仓）
  - 正确做法：打包产物放在 GitHub Releases 的 assets 里，Tampermonkey 从 release 拉取更新
  - 已执行：git push origin --delete dist（远端 dist 分支 refs/heads/dist 已删除）

实现（Tampermonkey 自动更新业界标准做法，避免 releases/download 直链 302 问题）：
  1) vite.config.js 元信息调整：
     - @updateURL / @downloadURL 固定指向 master 分支根目录的 meta.user.js
       URL = https://raw.githubusercontent.com/javalittleman1/request-url-param/master/meta.user.js
     - meta.user.js 仅含脚本头（体积 ~2.4 KB，极小，只保存 @version/@require/@grant 等元信息）
     - Tampermonkey 定时拉 meta.user.js 读取 @version，版本更高就更新

  2) meta.user.js（极小指针文件）提交到 master 根目录
     - 这是唯一"需要入源码仓"的文件：它只是头信息指针，不包含任何打包 / Vue 代码，
       和 dist/ 目录（完整打包产物 56.9 kB）有本质区别。
     - 自动更新链路必须保证此 URL 可直接访问（raw.githubusercontent.com → HTTP 200）

  3) workflow 彻底重写（删除 push dist 分支步骤）：
     name = 构建油猴脚本并发布到 GitHub Releases
     Steps:
       1/7  checkout master
       2/7  setup-node 22 LTS + corepack:true
       3/7  pnpm/action-setup v10.30.1（双保险：packageManager + with.version）
       4/7  pnpm install
       5/7  pnpm build → 产出 dist/rup-tampermonkey.user.js，输出 version 到 GITHUB_OUTPUT
       5.1/7 upload-artifact v4（Actions 手动下载缓存）
       6/7  awk 提取头生成 meta.user.js（供 Release assets + 同步 master 根目录副本）
       7/7  softprops/action-gh-release@v2
            tag_name = v{version}（如 v0.2.1）
            files    = dist/rup-tampermonkey.user.js + dist/meta.user.js
            make_latest = true
            body     = 中文 Release Note（下载指引 + 自动更新说明）

验收：
  - 本地构建 OK（56.94 kB，@version=0.2.1，@updateURL=@downloadURL 指向 master/meta.user.js）
  - 本地 meta.user.js 生成 OK（2460B，仅含 ==UserScript== 头块）
  - 远端 dist 分支已删除
