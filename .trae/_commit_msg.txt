build: 产物迁出源码仓，启用 Actions CI 构建+dist 分支自动部署

1) 构建产物与源码分离
  - 从源码仓 master 分支移除 dist/（git rm --cached）
  - .gitignore 恢复忽略整个 dist/ 目录
  - 构建物仅存放在独立的 dist 分支（不和源码混存，符合您的工程要求）

2) 新增 GitHub Actions 工作流
   文件：.github/workflows/build-and-deploy-dist.yml
   触发：push master / 手动 workflow_dispatch
   步骤：
     ① actions/checkout@v4
     ② actions/setup-node@v4   Node 22.x
     ③ pnpm/action-setup@v4
     ④ pnpm install --frozen-lockfile=false
     ⑤ pnpm build
     ⑥ actions/upload-artifact@v4   上传 dist/rup-tampermonkey.user.js（90 天，方便手动下）
     ⑥ git worktree 方式把 /dist/ 子目录结构（dist/rup-tampermonkey.user.js）
        推送到仓库独立的 dist 分支，用 GITHUB_TOKEN + x-access-token 写回
   分支 dist 上的文件：
     README.md（dist 分支说明）
     dist/
       rup-tampermonkey.user.js

3) 油猴脚本头元信息重写（vite.config.js）
   updateURL = downloadURL
     = https://raw.githubusercontent.com/javalittleman1/request-url-param/dist/dist/rup-tampermonkey.user.js
     分支 = dist | 路径 = dist/rup-tampermonkey.user.js   完美对应 worktree 部署结构

4) 版本号单一真相源
   vite.config.js 不再写死 version，改为 node:fs 读 package.json.version
   本次升级：0.1.0 -> 0.2.1
     理由：@updateURL 架构改动 + 修改列表联动闪烁/定位/框住功能 + 多项菜单/通知修复

5) 本地手动 bootstrap
   当前最新构建（0.2.1）已经用临时仓库方式强制推到远端 dist 分支，
   新的 Tampermonkey 自动更新 URL 立即可用，不用等第一次 Actions 跑完
